# Open problems

A loop that stops changing is only the first requirement. We also need the same equations and answer under different schedules, types that admit runtime values, and affordable re-checking after edits. The [facts](facts.md) and [attempts](attempts.md) distinguish pinned measurements, executable models and proofs. Older measurements must be refreshed before describing current main.

1. **Discover the same equations.** Dispatch targets, return and parameter slots, closure slots and their writers are discovered during inference. Different schedules can therefore solve different systems (F5, F16). Can the complete logical structure be declared from the program, or discovered monotonically without retracting edges or changing reference routing? The check is matching final structure digests across shuffled schedules, complete read/write membership, matching carried-state answers and zero extra-round movement. Predeclaration additionally requires matching start/end structure. 2. **Make every writer obey its algebra.** The merged parameter and ivar join repairs are useful foundations, but return replacement, narrowing and history-sensitive size cuts remain separate obligations. For each carried slot, declare its join and its writer transfers. At the join, contributor permutations and regroupings must give the same result: the join must be commutative, associative and idempotent, with pending as its identity. Source-priority transfers, which prefer one writer over another, are not joins and need their own justification: their priority semantics, monotonicity as inputs grow, and preservation of possible values. Widening must preserve possible values too. F14 shows why better precision counts alone cannot validate a merge rule. 3. **Distinguish pending, unresolved and gradual values.** Pending inference contributes no evidence; unresolved dispatch records a modeling gap; gradual values retain dynamic possibilities. These meanings must survive producers, sharing, joins, dispatch and export. Pending is not language-level non-return: treating it as `Bottom` fails the F19 runtime witnesses. F18's keep-unresolved control avoids false nil-only receivers but loses precision and hides errors. Progress requires producer-specific semantics, the paired error census, fixed coverage denominators and the oracle together.
