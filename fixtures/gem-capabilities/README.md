# Gem capability contracts

A small opt-in CLI corpus, not a gem registry or a compiler support claim.
The shared capability is **declarative class bodies across local inheritance**:
Alba 4.0.0 accumulates inherited/nested attributes; dry-validation 1.11.1 composes
an inherited params schema with a derived rule. Inputs and literal assertions are
independent of compiler output. There is no gem/compiler vendoring or runtime fix.

Two new contracts distinguish false from nil, presence from omission, repeated
declarations from replacement, and the 17/18/19 validation boundary. Alba uses
small record objects with asymmetric IDs (41/42 vs writer 23). dry-validation
coerces string ages and preserves false/nil. Its derived class explicitly declares
`params` to compose the superclass schema; merely subclassing does not inherit
a usable schema in 1.11.1. Assertions were not weakened to hide this API contract.

The default regression core is the two new contracts plus historical Alba,
dry-validation and bcrypt (a Ruby positive control). The remaining historical
cases are retained, and explicitly `not-run` in a core execution. This change
does not resurvey JSON, use private apps, start servers, dispatch HTTP, open a DB,
or exercise Rails engine lifecycle. No existing Alba or JSON regression is changed.

## Four separate lanes

1. **CRuby4 + original gem**: frozen lock, install/check, original gem API and
   unmodified independent assertion. Invalid references block downstream lanes.
2. **Roundhouse → Ruby4**: strict/continue library checks **and analyzed controller
   consumers**, ordinary emit, residue diagnostics, syntax, unchanged output
   Gemfile/bundle, no-preload `require './main'` boot, then independent contract.
   Consumers are explicit fixtures with zero-argument `index` actions; parameterized
   APIs stay in analysis helpers. They are not generated by rewriting Ruby text
   and are not dispatched or claimed as whole-app consumer runtime passes.
   No original classes/gems are injected into output. Boot performs no dispatch
   or adapter configuration; it is not a Rails boot or an app integration pass.
3. **Original gem source → Spinel**: original installed entry files by explicit
   relative paths, original transitive load roots, require gate, real compile,
   artifact hash and native binary execution when compilation succeeds.
   Optional/dynamic requires remain compiler inputs, not patched-away sources.
   Native CRuby extensions cannot become passes via Spinel package replacements.
   Spinel searches its bundled libraries/packages before `-I` roots. Without
   transitive provider evidence, a successful source projection stays `blocked`,
   not an original-gem-source pass. This runner does not add a resolver registry.
4. **Roundhouse → Spinel**: unchanged emitted model aggregator/runtime, byte-identical
   assertion, real compile and native binary run. This is a **module contract**;
   full Spin project/Rails boot is separately `not-run`, never inferred from it.

Every stage records argv/cwd/explicit environment, stdout/stderr, exit/signal,
and a scoped status. Exit zero with wrong stdout is `contract-fail`; nonzero is
`runtime-fail` or `rejected`; missing output is `emission-missing`; absent/wrong
build provenance is `provenance-missing`/`provenance-mismatch`. Blocked, rejected,
skipped and not-run are not passes. A successful library check says nothing about
consumer typing or emitted runtime support. Warnings/notes and `lower_residue`
are preserved in full, not hidden behind an exit code.

Unlike the frozen observation script, the new CLI exits **1 if any requested
lane is not passing**. A `--reference-only` execution gates only the CRuby lane;
its skipped compiler lanes are still recorded as `not-run`. Existing results
directories are never overwritten. This opt-in runner is not added to CI.

## Reproduce

Prerequisites: Linux x86-64 matching the locks; Ruby **4.0.7p0**, Bundler **2.6.9**,
Rust/Cargo **1.98.1**, C compiler, make, libclang development library (Rust bindings)
and libsqlite3 development library (output dependency installation). Minitest
**6.0.6** is needed only for runner tests. Gem installation uses RubyGems; it does
not contact an application service.

```sh
gem install bundler -v 2.6.9 --no-document
gem install minitest -v 6.0.6 --no-document
git remote add upstream https://github.com/rubys/roundhouse # if absent
git fetch upstream main
git rev-parse upstream/main
# Compiler sources chosen for this snapshot:
# f3d192810b53c61a73a52017e23d67df80265f72

# Each build output must be new. build.rb owns an exclusive Cargo target and
# records source HEAD/tree/origin/upstream/full diff, build commands and binary hash.
ruby fixtures/gem-capabilities/build.rb roundhouse "$PWD" /tmp/capability-rh-build
git clone https://github.com/matz/spinel /tmp/capability-spinel-source
git -C /tmp/capability-spinel-source checkout --detach 7147b681fd885ac1038f78474b010f2ab2d58402
ruby fixtures/gem-capabilities/build.rb spinel /tmp/capability-spinel-source /tmp/capability-sp-build

ruby fixtures/gem-capabilities/test_runner.rb
ruby scripts/check-gem-capabilities.rb --out /tmp/capability-core \
  --roundhouse /tmp/capability-rh-build/receipt.json \
  --spinel /tmp/capability-sp-build/receipt.json
# Expected exit1 on the recorded compiler pins; inspect results.json, not only exit.

ruby scripts/check-gem-capabilities.rb --reference-only \
  --cases declarations-alba,declarations-dry --out /tmp/capability-reference
# Expected exit0; exactly the original-gem reference contracts, not runtime support.
```

Use `--cases id,id` to select an explicit subset. `--cases all` is an opt-in wider
run, **not** what this snapshot executed. Each execution keeps actual input and
output locks, exact emitted artifacts, hashes, original source/package hashes and
raw commands in its results directory. Output dependencies are freshly resolved;
for identical output bundle reproduction use the recorded output locks, not a
claim that a later resolve is the same snapshot.

Compiler provenance compares sources to the chosen pins. Only this corpus and
its CLI may differ from the Roundhouse compiler pin; all other tracked differences
or untracked source files are rejected. The working HEAD/tree/full diff are still
recorded, so a corpus commit is never mislabeled as an unchanged compiler checkout.
The receipt also binds the actual binary SHA256 and version stamp to a successful
build. Spinel uses `make -B -j4` to force rebuilding ignored objects; an incremental
`make` receipt is rejected even if its exit/version/hash look successful. It is
local evidence, not an adversarially signed software attestation.
