## Exact Current dependencies

The real app declares only `attribute :session, :user`, with no explicit default.
Original boot confirms both defaults are the actual `NOT_SET` sentinel,
`Current.new.attributes == {}`, no reset callbacks, and thread isolation. There
is **no app-declared non-nil/callable Current default to exercise**. No synthetic
attribute/default declaration was added.

The private delivery's `evidence/next/dependencies.json` (31 exact bodies) includes source lines
and full-file SHA256 identities from the unchanged app and locked Rails Git
revision. The decisive original Rails bodies are:

```ruby
def initialize
      @attributes = resolve_defaults
    end

def resolve_defaults
        defaults.each_with_object({}) do |(key, value), result|
          if value != NOT_SET
            result[key] = Proc === value ? value.call : value.dup
          end
        end
      end

def reset
      run_callbacks :reset do
        self.attributes = resolve_defaults
      end
    end
```

These are `current_attributes.rb:205–207,235–241,228–232`. Initialization and reset
must resolve fresh storage, not retain a boot sample. Skipping NOT_SET means an
**absent key**, not an explicit nil default. A declared Proc default would execute
on each resolution; a non-Proc value would be duplicated. Those two branches are
source obligations, not positively exercised Current branches in this app.

The `defaults` getter is a generated `class_attribute` method. Its generator in
`core_ext/class/attribute.rb` checks `defined?(@defaults)` and otherwise reads
`self.class.defaults`; the class getter calls `__class_attr_defaults`. The actual
ClassAttribute implementation closes over `value`, mutates it on the same owner,
and creates a new inherited-owner definition otherwise. The live defaults Hash
contains Object sentinels; it is not an admissible scalar constant or a frozen
value substitute. The dependency evidence includes both generator and redefiner.

Exact registry bodies are also retained: `instance` uses
`current_instances[current_instances_key] ||= new`; the key memoizes
`name.to_sym`; `ExecutionContext.record` stores a freshly constructed Record in
IsolatedExecutionState. Record initializes separate mutable `@store`,
`@current_attributes_instances`, and `@stack`, with real push/pop behavior.
`clear_all` resets the old objects **before clearing the registry**. Ordinary
reset preserves singleton identity; clearing causes the next lookup to construct
a different object. The public class delegates are generated by Rails, not
provided by the contract.

Instance reset reaches the real `Callbacks#run_callbacks`, which consults
`__callbacks` and has nonempty-chain compile/invoke branches. Scoped `set` reaches
the real `Object#with` and its ensure restoration. The current empty callback
chain is an observation, **not permission to erase other branches or freeze it**.
The app's `session=` additionally calls `super`, `present?` and `session.user`;
these contracts leave Session/User/Account behavior outside their positive domain.

Current instance methods. `arrangement` selects the **actual** ArrangementHelper
module and invokes it using ordinary `Object.new.extend`. No namespace rename,
copied class, bridge method or framework implementation is injected. The current
root API rejects those shapes; their generic support remains a parent decision.

There is no app-declared non-AR Rails `delegate` macro outside the framework's

Page's block `cattr_accessor` and ActionText::Markdown's `mattr_accessor` also

Redcarpet renderer, and the actual initializer overwrites it with a Proc that
builds a fresh MarkdownRenderer. Exact declarations/initializer are included in
the evidence; this callable is not a Current default.
